## Understanding and remembering the structure
Can become a spaced repetition exercise. Perhaps folder by folder, parent through to children. Essentially just an exercise in filling in the missing file. If we can get information about the purpose of each file/folder, we could then remember that info too. Could we have the Nautilus app ask the user for their definition of files and folders? Use it as an exercise in retrieval/elaboration?

## What are the dependencies
Use spaced repetition to remember which libraries are being used in the project. Spaced repetition to remember the arguments passed to each library function/class.

Use retrieval practice to test learning about particular dependencies, cross check with the official docs. This could be a powerful exercise:

1) Ask for the user to write everything they think they know about a thing, starting at the high level, module/library level.
2) Compare with the docs and describe where they were right/wrong.
3) User reads the docs
4) Another retrieval practice later (should be better!)
5) Compare with their docs and their last attempt

Prioritise learning hierarchically:
1) Module/Library definitions
2) Function/Class definitions - for those used in the project
3) Function/Class arguments
4) Function/Class definitions - for those not in the project (depth!)

## Elaboration
This may be mostly up to the user to think more deeply about what they are learning. However, we could add explicit steps, especially during the the early Vocabulary stages of their learning. We can prompt the user to write and elaborate on their current/expected understanding of a topic within a project. We can also look for other points in their learning journey to prompt moments of reflection and encourage deeper thinking occasionally.

## Interleaving
We can encourage the user to regularly switch to different topics they have flagged for learning. Say they are learning Python and Java. We could have the user spend equal amounts of time studying both.
